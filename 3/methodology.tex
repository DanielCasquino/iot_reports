\subsection{Components and CP2 configuration}
The CP2 implementation uses an ESP32 development board, an LDR, a fixed
resistor, a breadboard, jumper wires, and a USB cable. The LDR and the
fixed resistor form a voltage divider. The divider output is connected to
GPIO35, which is used as an ADC input by the ESP32. The exact resistance
value and the orientation of the divider must match the physical circuit
demonstrated during the checkpoint; changing either one changes the
direction and scale of the ADC response.

The ESP32 is programmed with the Arduino IDE and the ESP32 board support
package. The sketch uses the \texttt{WiFi.h} library for network
connectivity and PubSubClient 2.8 for MQTT communication. The serial
monitor is configured for 115200~baud. Network credentials are stored in
\texttt{secrets\_local.h}, which is intentionally excluded from the
repository. The broker address is supplied through \texttt{mqtt\_broker}
and the broker listens on the standard non-TLS MQTT port, 1883. The
client publishes the raw ADC value as a text payload to the
\texttt{lab/ldr} topic.

The program first waits until the ESP32 is associated with the configured
Wi-Fi network. It then configures the broker address and port. During each
iteration, \texttt{analogRead(35)} acquires the raw ADC code, the value is
printed to the serial monitor, and the MQTT connection is established if
necessary. After \texttt{mqtt.loop()} services the client, the value is
published and the program waits 1000~ms before the next iteration. The
1000~ms delay is a minimum application delay rather than an exact sampling
period because ADC acquisition, Wi-Fi processing, and MQTT operations add
execution time.

\subsection{Hardware and communication sequence}
The complete data path is shown in Fig.~\ref{fig:cp2-block-diagram}.
The sensor circuit produces an analog voltage, the ESP32 samples it,
and the MQTT broker forwards the resulting payload to a subscribed
client. Because \texttt{analogRead} returns an ADC code rather than a
calibrated illuminance value, the reported payload is intentionally
described as a raw LDR reading.
