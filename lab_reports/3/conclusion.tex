This laboratory helped us understand how to connect a physical circuit to a network and monitor or control it from another computer. Installing Mosquitto was straightforward, but having the broker running was not enough: the ESP32 also needed the correct laptop address and port, and the firewall had to allow the connection. We therefore recommend checking these settings before looking for errors in the sensor or MQTT code. The LDR readings and the blind-control experience showed how the same communication model can support both monitoring and commands, with the automatic and manual behavior demonstrated in the videos. The intermittent buzzer response also reminded us to test each component separately when the rest of the system appears to work. One of the most useful lessons from connecting the Mega to the ESP32 was that sharing a communication protocol does not mean sharing the same voltage levels: the Mega's TX signal needs a voltage divider before reaching the ESP32 RX input to avoid damaging it. We recommend checking the divider connections and measuring its output before connecting the boards. Finally, because the ESP32 needs network credentials to reach the broker, the Wi-Fi password should be kept in a separate local configuration file excluded from the shared code. This makes it easier to share the programs and reproduce the checkpoints without accidentally exposing credentials.
